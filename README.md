# AmneziaKeyService

Сервис для автоматической генерации VPN-ключей AmneziaWG и выдачи конфигов в формате AmneziaVPN (`vpn://`).

## Требования

- [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0) (RC или Preview)
- MongoDB 6+
- AmneziaWG-сервер (уже настроен с Docker-контейнером `amnezia-awg`)

## Быстрый старт

### 1. Создайте владельца и добавьте сервер через API

Сначала запустите worker: только он применяет миграции. Затем создайте
владельца из `ADMIN__USERNAME`/`ADMIN__PASSWORD` и добавьте сервер через
`POST /api/servers` или мастер панели. Этот путь записывает современный
`server_config` и шифрует SSH-пароль либо приватный ключ до сохранения в MongoDB.
Не создавайте документ узла напрямую через `mongosh`: плоская legacy-схема
больше не поддерживается.

### 2. Настройте appsettings.json

```json
{
  "MongoDb": {
    "ConnectionString": "mongodb://localhost:27017"
  },
  "Jwt": {
    "Secret": "минимум-32-символа-случайная-строка"
  }
}
```

Используйте `appsettings.Development.json` или переменные среды для секретов:
```bash
export Jwt__Secret="your-random-secret-here"
```

### 3. Запустите сервис

```bash
cd src/AmneziaKeyService.Api
dotnet run
```

Swagger UI: http://localhost:5000/swagger

## API

### Подключение уже настроенного VPN-сервера

В меню **Серверы → Подключить существующий** укажите адрес, SSH-порт и
пароль либо приватный ключ. Нажмите **«Найти установленные протоколы»**,
проверьте найденные порты, подсети и число существующих подключений, затем
выберите протоколы и нажмите **«Подключить выбранные»**.

Поддерживаются стандартные работающие контейнеры `amnezia-wireguard`,
`amnezia-awg`, `amnezia-awg2`, `amnezia-awg3`. AWG3 определяется также по
`HeaderProtectionKey` в конфигурации `amnezia-awg2`. Xray и контейнеры с
произвольными именами в этом режиме пока не импортируются.

Поиск и импорт выполняют только чтение по SSH: не устанавливают пакеты,
не меняют firewall, не перезапускают контейнеры и не переписывают конфиги.
Перед импортом конфигурация перечитывается; при изменениях нужно повторить
поиск. Остановленный контейнер, недоступные ключевые файлы, несовпадение
ключей/портов или клиентов в конфиге и работающем интерфейсе блокируют
подключение соответствующего протокола. Поддерживается один IPv4-адрес
интерфейса с маской /8–/30, первый адрес подсети (например, `10.8.1.1/24`),
и один публичный UDP-порт либо host networking. Адрес узла должен быть
доступен и по SSH из панели, и для VPN-клиентов.

Существующие подключения продолжают работать, но их владельцы, сроки,
квоты и история из потерянной базы не восстанавливаются. Они учитываются
как подключения без выданного панелью ключа. Занятые адреса берутся из
конфига при каждой новой выдаче. Перед подключением сохраните отдельную
копию конфигураций узла; не управляйте им одновременно из нескольких панелей.
Для проверки повторного добавления используйте одинаковый адрес и SSH-порт,
а не разные DNS-имена одного узла.

API (владелец/администратор): `POST /api/servers/discover` принимает SSH-доступ
и возвращает безопасный список протоколов с `revision`; `POST /api/servers/import`
принимает тот же доступ, метаданные, `revision` и выбранные имена `containers`.
Параметры протоколов и секреты перечитываются сервером, а не принимаются от
браузера. SSH-секреты шифруются перед сохранением. Импорт создаёт один узел
с несколькими протоколами и запись аудита `server.imported`.

Проверки: `dotnet run --project tools/VerifyServerImport` (SSH и репозиторий
изолированы; реальные протоколы на VPS не затрагиваются).

### Очистка и удаление узла

В карточке узла раздел **«Очистка и удаление узла»** доступен администратору.
Для обеих операций нужно ввести точное имя узла в диалоге подтверждения.

- **Очистить VPN на узле** — удалить зарегистрированные в панели VPN-контейнеры
  вместе с конфигурациями. Все их подключения, в том числе созданные вне панели,
  перестанут работать. Ключи панели помечаются отозванными, их секреты удаляются,
  история выдачи сохраняется. Карточка, адрес и SSH-доступ остаются; после очистки
  статус — «без протоколов», можно установить VPN заново.
- **Удалить узел из панели** — удалить карточку и сохранённый SSH-доступ.
  На сервере ничего не меняется. Операция запрещена, пока есть неотозванные ключи
  панели, включая ожидающие отзыва, приостановленные и истёкшие. История ключей
  и журнал сохраняются.

Операции выполняет worker в общей очереди узла, последовательно с установкой
и выдачей ключей. Ход и ошибки отображаются в карточке, идентификатор задачи
сохраняется в URL. При частичной очистке выдача новых ключей блокируется;
после устранения ошибки очистку можно запустить повторно. Ключи отзываются
в базе только после подтверждения отсутствия соответствующего контейнера.
Автоматического повторного удаления после сбоя нет.

Очистка поддерживает стандартные зарегистрированные контейнеры WireGuard,
AWG 1/2/3 и Xray. Посторонние контейнеры, образы, Docker, настройки хоста
и каталоги сборки сохраняются. Контейнеры с внешними томами/каталогами данных
отклоняются до начала удаления; штатный bind `/lib/modules` допускается и
остаётся на хосте. Незарегистрированные контейнеры автоматически не удаляются.

API: `POST /api/servers/{id}/cleanup` и `DELETE /api/servers/{id}` принимают
JSON `{"confirmationName":"точное имя узла"}` и возвращают `202` с `jobId`.
Состояние читается через `GET /api/jobs/{jobId}`. Изменение адреса или набора
протоколов после постановки в очередь отменяет операцию до SSH-действий.

Проверки: `dotnet run --project tools/VerifyServerMaintenance`; параметр
`-- --mongo=mongodb://127.0.0.1:27017` добавляет проверки на отдельной временной
базе с последующим удалением только этой тестовой базы. Реальные VPN-узлы
в проверках не используются.

### Обновление протоколов и выбор в боте

В карточке существующего сервера нажмите **«Добавить / обновить протокол»**.
AmneziaWG нового семейства реализован по релизу AmneziaVPN 5.0.2.1 и отображается
как **AmneziaWG 3.1**. Он устанавливается отдельным контейнером рядом с AWG 1/2.
Пустые поля порта и подсети означают автоматический выбор; явные значения
проверяются на пересечения. Повторная установка поверх существующего контейнера запрещена.
Для новых ключей обновите приложение AmneziaVPN.

Кнопки **«Отключить выдачу» / «Включить выдачу»** управляют доступностью новых
ключей. Они не останавливают контейнер, не отзывают старые ключи и не отключают
их мониторинг. Можно отключить выдачу для всех протоколов сервера.
В боте первичная выдача и «Новый ключ» открывают выбор доступного протокола;
ранее выданные ключи доступны через «Мои ключи».

- `POST /api/servers/{id}/protocols` — установка новой версии рядом со старой;
- `PUT /api/servers/{id}/protocols/{protocolId}/availability`, тело
  `{ "enabled": false }` — выключить выдачу новых ключей.

Состояние установки и журнал доступны в карточке сервера. При неудаче
существующие протоколы сохраняются. Если остался контейнер незавершённой установки,
повторный запуск не удаляет его автоматически: сначала требуется диагностика на узле.
Проверки: `dotnet run --project tools/VerifyProtocols`; для проверки MongoDB
добавьте `-- --mongo=mongodb://127.0.0.1:27017` (создаётся и удаляется отдельная тестовая БД).

### `POST /api/auth/register`
Регистрация нового VPN-пользователя.
```json
{ "username": "alice", "password": "securepassword" }
```
Ответ: `{ "token": "eyJ..." }`

### `POST /api/auth/login`
Аутентификация.
```json
{ "username": "alice", "password": "securepassword" }
```

### `GET /api/vpn/config`
_(требует Bearer JWT)_

Если у пользователя на этом узле уже есть активный ключ — отдаёт готовый
VPN-конфиг сразу, `200`:
```json
{
  "vpnUri": "vpn://eJy...",
  "clientIp": "10.8.1.2",
  "clientPubKey": "abc123..."
}
```

Если ключа ещё нет, выдача синхронно по HTTP не делается — она идёт по SSH
в фоновом процессе (worker) и не укладывается в один запрос. Ответ — `202`
с идентификаторами заявки:
```json
{ "eventId": "665f...", "keyId": "665f..." }
```

Порядок для клиента: опрашивать `GET /api/events/{eventId}`, пока статус
не станет терминальным (`succeeded`/`failed`/`canceled`); по `succeeded`
повторить запрос `GET /api/vpn/config` — сработает быстрый путь выше.

`vpnUri` можно вставить в AmneziaVPN (Добавить → Вставить ссылку) или сгенерировать QR-код.

### Массовые уведомления Telegram

Раздел панели «Рассылки» доступен владельцу и администратору. API не отправляет
сообщения внутри HTTP-запроса: он создаёт кампанию и устойчивую очередь
получателей в MongoDB, которую с ограничением скорости разбирает процесс бота.

- `GET /api/notifications/audience` — число активных пользователей с Telegram;
- `GET /api/notifications` — история и прогресс кампаний;
- `POST /api/notifications` — создать и сразу запустить кампанию;
- `POST /api/notifications/{id}/cancel` — остановить ещё не выполненные доставки.

Текст отправляется без parse mode и ограничен 4096 символами. По умолчанию
диспетчер отправляет не более 20 сообщений в секунду, повторяет временные
ошибки и учитывает Telegram `retry_after`.

## Формат `vpn://`

Совместим с [exportController.cpp](../amnezia-client-dev/client/ui/controllers/exportController.cpp):
1. JSON → UTF-8 bytes
2. qCompress: 4 байта big-endian (размер оригинала) + zlib RFC 1950
3. Base64 URL-safe без padding
4. Префикс `vpn://`

## MongoDB-схема

### Коллекция `server_config`
Один документ с параметрами AWG-сервера (SSH-кредиты, пути к ключам, параметры обфускации Jc/S1-S4/H1-H4).
При первом запросе `/api/vpn/config` сервис подключается по SSH, читает `awg0.conf` и кэширует параметры обратно в MongoDB.

### Коллекция `clients`
Один документ на пользователя: `username`, `passwordHash` (BCrypt), `assignedIp`, `clientPrivKey`, `clientPubKey`, `pskKey`, `vpnConfigJson`.
