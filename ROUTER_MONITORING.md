# Наблюдение за домашним роутером

Раздел **Наблюдение → Роутеры** связывает отдельное WireGuard-подключение
с пользователем Telegram. Роутер сам подключается к VPS: белый IP дома,
проброс портов, новая прошивка и дополнительное устройство не нужны.
Статусы показывают доступность соединения. Потерю электричества невозможно
надёжно отличить от сбоя домашнего интернета или самого роутера.

## Подготовка и обновление сервиса

1. Обновите Worker, API, Bot и сборку панели вместе. Сначала запустите Worker:
   он применит миграцию `014_router_monitoring`, остальные процессы дождутся
   готовности схемы. Новые коллекции: `router_monitors` и `router_history`.
   Они работают и на standalone MongoDB, replica set не требуется.
2. Включите `Polling__Enabled=true` в Worker. При выключенном опросе выдача
   выделенного ключа и наблюдение не выполняются. Существующие интервалы
   статистики трафика сохраняются; узлы с роутерами проверяются каждые
   30 секунд или чаще, если `Polling__StatsIntervalSeconds` меньше 30.
   К интервалу добавляется длительность опроса узлов.
3. Запустите Bot с `TelegramBot__Token`. Очередь уведомлений роутеров
   независима от настроек массовых рассылок `Notifications`.
4. На доступном VPN-узле должен быть установлен и разрешён к выдаче **обычный
   WireGuard**. AmneziaWG не подходит штатному WireGuard-клиенту Archer AX53.
   Установка обычного WireGuard доступна в карточке сервера; UDP-порт
   протокола должен быть доступен из домашней сети.
5. Получатель должен зарегистрироваться в боте по пригласительному коду,
   оставаться активным пользователем и не блокировать бота.

## Подключение Archer AX53

1. Откройте **Роутеры → Добавить роутер**, задайте название, получателя Telegram
   и узел. Worker выдаст отдельный бессрочный ключ без квоты трафика.
2. В карточке откройте **Подключение → Скачать .conf**. Если ключ ещё готовится,
   повторите через полминуты. Используйте именно этот файл, а не обычный VPN-профиль.
3. В штатной панели TP-Link откройте VPN Client → Add Profile → WireGuard,
   импортируйте файл. NAT оставьте включённым, VPN Kill Switch — выключенным,
   сохраните и включите профиль.
4. В файле уже заданы `PersistentKeepalive = 25`, маршрут `AllowedIPs` только
   к внутреннему VPN-адресу сервера `/32` и удалена настройка DNS. Основной
   домашний интернет не направляется через VPS. Приватные данные профиля
   доступны только администратору панели, ответ помечен `Cache-Control: no-store`.
5. Дождитесь «На связи» и нажмите **Тестовое сообщение** во вкладке настроек.
   Проверьте профиль без подключённых домашних устройств: прошивка должна
   поддерживать туннель сама. Затем проверьте восстановление после перезапуска
   роутера. Если профиль не работает без устройства в списке VPN-клиентов,
   этот способ на данной прошивке не подтвердился — это нельзя исправить
   изменением серверного детектора.
6. Для проверки потери связи выключите роутер на 5–6 минут и включите обратно.
   Сверьте историю с уведомлениями. Сам сервис не меняет настройки роутера.

Совместимость автозапуска и keepalive на указанной прошивке должна быть
подтверждена на реальном устройстве; локальные тесты сервиса её не проверяют.
Один профиль используйте только на одном роутере: копирование на другое
устройство даст ложное подтверждение домашней связи.

## Состояния и точность

### Ошибка `read_container_file` при установке обычного WireGuard

В прежнем установщике пути к публичному ключу и PSK ошибочно указывали на
`/opt/amnezia/awg/`, хотя upstream создаёт их в `/opt/amnezia/wireguard/`.
Исправленный установщик использует каталог конфигурации выбранного протокола.
Миграция `015_wireguard_key_paths` исправляет только известные неверные пути
в сохранённых записях обычного WireGuard, сохраняя пользовательские пути,
ключи, идентификаторы и состояние установки. Обновляйте backend целиком,
Worker запускайте первым.

Если установка уже завершилась ошибкой, контейнер мог остаться работающим.
Миграция не помечает его установленным: перед восстановлением нужны проверка
файлов и интерфейса на VPS. Повторная установка поверх существующего контейнера
будет отклонена. Для диагностики без вывода содержимого ключей:

```bash
sudo docker ps -a --filter name=amnezia-wireguard --format '{{.Names}}: {{.Status}}'
sudo docker exec amnezia-wireguard ls -l /opt/amnezia/wireguard/
sudo docker exec amnezia-wireguard wg show wg0 listen-port
```

### Значения статусов

| Статус | Значение |
|---|---|
| Ожидает подключения | Готовится ключ либо ещё не было handshake |
| На связи | Возраст последнего handshake не превышает порог |
| Нет связи | Handshake старше порога, а узел успешно опрашивается |
| Нет данных | Сбой SSH/опроса, рассинхронизация часов или данные старше 120 секунд |
| Требуется настройка | Ключ не создан/отозван либо peer отсутствует на узле |
| На паузе | Администратор приостановил наблюдение |

Порог по умолчанию — 240 секунд, допустимо 180–3600. Keepalive каждые 25 секунд
не означает новый handshake каждые 25 секунд. Отключение определяется по
возрасту handshake, затем уведомление выдерживается ещё 30 секунд для подавления
быстрых переключений; добавляются время опроса и доставки Telegram.
Короткий перебой может остаться незамеченным. Время события — момент обнаружения,
а длительность перерыва — приблизительное время между обнаружением потери
и восстановлением связи. Telegram указывает UTC, панель — местное время браузера.

Сбой VPS, SSH или Worker не обозначается как отключение света. Перерыв
наблюдения разрывает подсчёт длительности отключения. При недоступности самого
VPS сервис не сможет прислать сообщение. После восстановления свежий handshake
может вызвать новое подтверждение связи без длительности перерыва.

## Пользователи, уведомления и ключи

- Просмотр доступен ролям с `panel:read`; создание, настройки, скачивание
  профиля, тест и удаление наблюдения — с `panel:admin`.
- В боте добавлены `/routers` и **Мои роутеры**. Пользователь видит только
  свои роутеры и может включить или выключить их уведомления в личном чате.
- Отключение уведомлений сохраняет историю; пауза останавливает наблюдение.
- Смена получателя отменяет ещё не отправленные сообщения прежнему пользователю.
  Уже переданный в Telegram запрос отозвать нельзя. Привязка получателя отдельна
  от владельца выданного VPN-ключа: существующий ключ при смене получателя
  не перевыпускается, в разделе «Ключи» остаётся первоначальный владелец.
- Первое успешное соединение также вызывает уведомление. Тест можно поставить
  в очередь раз в минуту; он работает даже при паузе и выключенных уведомлениях.
- История и очередь хранятся в MongoDB и переживают перезапуск. Панель показывает
  последние 100 событий, включая результат доставки. Удаление наблюдения
  архивирует карточку и сохраняет историю в базе, но не отзывает VPN-ключ.
  Отзыв выполняется отдельно в разделе «Ключи».
- Ключи с источником `router` не выдаются повторно обычным VPN-клиентам и
  не попадают в меню обычных ключей бота. В панели у ключа есть ссылка на роутер.
- После прерванной выдачи проверьте журнал и состояние peer на узле перед
  созданием замены: автоматического повторного выпуска потенциально созданного
  ключа нет.

Очередь проверяет актуальность состояния и получателя перед отправкой,
подавляет устаревшие уведомления, повторяет временные ошибки, учитывает Telegram
`retry_after`. Ошибки 400/403 завершают доставку; прочие временные ошибки — после
пяти попыток. При сбое между успешной отправкой и записью результата возможно
повторное сообщение: Telegram не предоставляет идемпотентный ключ отправки.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/routers` | Активные карточки |
| GET | `/api/routers/options` | Допустимые получатели и WireGuard-узлы |
| POST | `/api/routers` | Создание: `name`, `userId`, `serverId`, `protocolId` |
| GET | `/api/routers/{id}` | Состояние и настройки |
| PUT | `/api/routers/{id}` | `name`, `userId`, `paused`, `notificationsEnabled`, `offlineAfterSeconds`, `deliveryGeneration` |
| GET | `/api/routers/{id}/history` | Последние 100 событий |
| GET | `/api/routers/{id}/config` | JSON: `fileName`, `content` профиля |
| POST | `/api/routers/{id}/test` | Тестовое уведомление |
| DELETE | `/api/routers/{id}` | Архивация наблюдения без отзыва ключа |

Создание возвращает `202` и `id`; выдача ключа асинхронна. При сохранении
передавайте текущую `deliveryGeneration` из карточки; ответ `409` означает,
что нужно перечитать настройки или повторить сохранение после фонового опроса.

## Проверки разработчика

```bash
dotnet build AmneziaKeyService.sln
dotnet run --project tools/VerifyRouterMonitoring
dotnet run --project tools/VerifyRouterMonitoring -- --mongo=mongodb://127.0.0.1:27017
dotnet run --project tools/VerifyMonitoring
dotnet run --project tools/VerifyProtocols
```

Без `--mongo` выполняются проверки состояний, формата профиля, BSON и политик
API. С `--mongo` добавляются миграции, работа очередей, конкурирующие записи,
смена получателя и API на отдельной временной базе, которая удаляется в конце.
Эти проверки не обращаются к VPN-узлам и не отправляют сообщения Telegram.
Фронтенд: `npm run build`, `npm run lint`, `npm run verify:a11y` в `web/admin`.
